Remarques sur la fiche :

    Sur le problème (Partie 1) : Le texte explique bien le problème, mais il manque un chiffre pour prouver qu'il existe vraiment. Il faudrait ajouter une estimation, par exemple "environ 3 relances par dossier".

    Sur les indicateurs (Partie 2) : Pour le délai de validation, il faut préciser de quand à quand on chronomètre (par exemple : du clic "Soumettre" au clic "Valider").

    Sur les indicateurs (Partie 2) : Pour le taux de dossiers incomplets, il faut dire sur quelle période on compte (par exemple : sur une session complète).

    Sur les acteurs (Partie 3) : L'attente de l'encadreur est trop vague. Il faudrait préciser qu'il veut "voir la liste de ses étudiants et le statut de leur demande".

    Sur le périmètre (Partie 4) : Vous avez bien exclu le portail entreprise, mais il faut ajouter une petite phrase pour dire pourquoi (par exemple : "pour limiter le travail à 25 heures").

    Sur les objectifs SMART (Partie 5) : L'objectif "Refuser sans fuite" ne teste qu'une erreur (le code 403). Il faudrait aussi tester le cas normal (un refus autorisé qui fonctionne bien).

    Sur les objectifs SMART (Partie 5) : Il manque le "T" de SMART. Il faut ajouter une date ou un jalon pour dire quand l'objectif doit être atteint (ex : fin de la séance 9).

    Sur les risques (Partie 6) : Le risque de fuite de données est bien identifié, mais il manque une solution de secours au cas où ça arrive. Proposez d'effacer les vraies données et de remettre des données fictives.

Avis général : La fiche est claire et respecte le temps de travail. Il faut juste préciser un peu plus les indicateurs et ajouter des dates aux objectifs.
